# P05｜Work Reconcile 正确性闭环｜实现说明

## 实现范围

- `Work Baseline → Current Git Revision` 的事实差异计算；
- Git changed-files / diff Port；
- Work Reconcile Pending Candidate；
- 同一 Work 单一 Pending Candidate，多 commit 原位更新；
- lifecycle checkpoint；
- work-reconcile idempotency key；
- duplicate checkpoint dedupe；
- lost-hook recovery；
- Generic `post-commit` fallback；
- Evidence `PASS / FAIL / UNKNOWN` 基线；
- N0～N4 内部 Knowledge Impact 与 `AUTO / PROPOSE / STOP` 映射；
- `.continuum/**` / `.continuum-local/**` 不进入 Work business delta；
- `continuum reconcile` 与 `continuum lifecycle checkpoint` CLI。

## 核心正确性边界

```text
Project Snapshot Baseline != Work Baseline
```

Work Reconcile 始终从首次正式绑定时冻结的 `work_start_revision` 推导，不把绑定前的 Adapter / README / 其它工作提交归入当前 Work。

```text
Hook = wake-up signal
Git state = truth
```

因此 Hook 丢失后，后续 `reconcile / checkpoint` 仍可重新发现未收敛提交。

## Evidence

P05 不把 `UNKNOWN` 提升成 `PASS`。当前默认 Evidence Adapter 在未配置 Test / Review Authority 时返回 `UNKNOWN`；P06 完成 Change Reconcile 时必须尊重这一事实。

## 持久化边界

Work Reconcile 只写：

```text
.continuum-local/runtime.db
```

不产生 Durable Ticket Reconcile 文档；Change Durable Reconcile 属于 P06。
