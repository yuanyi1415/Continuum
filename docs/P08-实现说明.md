# P08｜Oh My Pi 原生适配实现说明

## 实现范围

- Project-local `.omp/extensions/continuum.ts`；
- `session_start / before_agent_start / session_stop / session_shutdown` 生命周期映射；
- explicit Work Intent 复用 Core；
- Worktree resume；
- Managed Work 单一 Ambient Widget；
- 简单 DECISION：`ctx.ui.select()`；
- Architecture DECISION：custom overlay；
- BLOCK：interactive input gate + before-agent abort + session-stop block；
- `/continuum-status`；
- `/continuum-off` Session Suppression；
- Headless lifecycle correctness 不依赖 `input` event；
- capability detection；
- `continuum host install omp`。

## 关键边界

1. OMP Adapter 不拥有 Project State；只转换事件和渲染交互。
2. `input` 仅作为 interactive BLOCK UX barrier，不作为 lifecycle correctness 必需事件。
3. 正常 Managed Work 只保留一个 Widget，不使用第二条 Continuum status line。
4. Session Suppression 不删除 Worktree Binding。
5. Hook/Extension 丢失后仍由 P05 state-derived reconcile 保证正确性。

## BLOCK Recovery Architecture Correction

真实 OMP TUI 验收发现旧版 BLOCK 会锁死整个 Session。已按 `ADR-009｜BLOCK 恢复语义` 修正：

```text
BLOCK
→ 返回设计 / Spec
→ 释放 Work Binding，但 blocker 仍 unresolved
→ 允许设计 / 研究工作
→ formal rebind 仍被拒绝
→ 用户显式 resolve blocker
→ 才允许重新 bind Work
```

OMP 正式 UI：

- BLOCK Overlay 提供“返回设计 / Spec”；
- 不再注册全局 `input` gate；
- `/quit / help / continuum-status` 不被 BLOCK 锁死；
- 新增 `/continuum-resolve-block`；
- `/continuum-off` 不能绕过当前 managed BLOCK。


## BLOCK Host UX 修正（v0.6）

OMP 在 Return to Design 后再次尝试进入被阻断 Work 时，不再在 lifecycle handler 内等待第二次 selector。Host 立即保持 BLOCK，并提示用户在设计 / Spec 真正修复后显式执行 `/continuum-resolve-block`。

`/continuum-resolve-block` 的命令调用本身就是显式确认，因此不再叠加第二次 UI 选择。解除阻断不会自动继续当前 implement turn；用户需重新发起正式 Work Intent。


## BLOCK phase correction (v0.7)

BLOCK resolution readiness is now a Core-owned runtime fact rather than an OMP UI inference.

```text
implementation BLOCK
→ return-to-design
→ pending interaction blockPhase=design
→ explicit resolve
→ resolved
```

OMP renders the implementation phase with the blocking overlay. In design phase, re-entering implementation is blocked immediately and the user resolves the blocker through the explicit `/continuum-resolve-block` command. Human UI waits inside lifecycle handlers are capped below the OMP host watchdog.


## v0.9｜设计冲突 UX 收敛

正式用户不再直接处理 `BLOCKED / resolve-block`。

流程：

```text
P03 暂停实现：发现设计冲突
→ 回到设计处理
→ 修改并提交相关 Spec / ADR
→ 再次 implement P03
→ Continuum 检测 committed design versions
→ 用户确认是否基于最新设计重新开始
→ 新 Work Binding + 新 Work Baseline
```

设计未发生变化时，只提示“P03 还不能继续”，不会要求用户理解内部 BLOCK 状态。
