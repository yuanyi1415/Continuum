# P09｜Doctor、迁移与故障恢复实现说明

## 范围

P09 只增加维护与恢复能力，不改变 Project / Change / Work / Snapshot / Interaction 的既有业务语义。

新增：

```text
continuum doctor
continuum doctor --recover
continuum migrate
continuum host doctor
```

## Doctor

`continuum doctor` 检查：

- Git 可用性与 repository identity；
- Durable schema 版本与结构；
- Current → Snapshot pointer；
- Change / Artifact / Relation 引用完整性；
- Artifact Authority 是否可解析；
- runtime.db 健康与 schema；
- Runtime Work Binding 是否引用仍存在的 Durable 节点；
- managed Work 是否存在丢 Hook 后未生成的 pending reconcile；
- Current Snapshot baseline 与 Git HEAD 之间的未收敛业务 diff；
- Codex / OMP Host Adapter 安装与 drift。

Doctor 默认只诊断，不修改 Durable Authority。

## Recovery

`continuum doctor --recover` 只自动执行可确定安全的 Runtime 恢复：

- runtime.db 缺失 → 创建新的 Runtime DB；
- runtime.db 损坏 → 原文件改名 quarantine 后重建，绝不直接删除；
- Runtime schema 旧 → 向前迁移；
- Runtime Binding 指向已不存在的 Durable 节点 → 清理 stale binding；
- Work Binding 仍在、Git 已产生新 revision、Hook 丢失 → 从 Git 状态重新生成 pending Work Reconcile。

若 runtime.db 已丢失，Continuum 不猜测原 Work owner。它只报告 Current Snapshot → Git HEAD 的 unreconciled business delta。

## Durable Migration

`continuum migrate` 显式迁移 Git-tracked Durable schema。

MVP 注册的历史迁移：

```text
schema_version 0 → 1
```

这是 structure-compatible prototype marker migration：迁移前先把完整 `.continuum/` 复制到：

```text
.continuum-local/backups/durable-schema-<timestamp>/
```

然后逐文件 validation + atomic write。

更高版本一律：

```text
CONTINUUM_SCHEMA_TOO_NEW
→ fail closed
```

不猜、不降级覆盖。

## Runtime Migration

Runtime schema 从 v1 升至 v2。

v2 不新增 Runtime Truth，只增加 Doctor / Recovery 查询索引。SQLite migration：

- transaction；
- idempotent；
- ordered；
- newer schema fail closed。

## Host Doctor

`continuum host doctor` 检查：

- Codex executable / capabilities；
- repo-local Codex hooks/config；
- OMP executable / extension capability；
- `.omp/extensions/continuum.ts` 是否存在；
- OMP extension 是否与当前发布资产一致。

Host 未安装或 adapter drift 默认是 WARN，不破坏 Durable Project State。

## Fail-safe 边界

以下情况 Doctor 只能报告，不能自动选择新事实：

- broken Current pointer；
- Durable YAML invalid；
- Durable schema newer than CLI；
- missing Artifact Authority；
- runtime 丢失后无法证明原 Work owner 的 Git delta。
