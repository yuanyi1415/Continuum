# Continuum 安装与快速开始

## 1. 前置条件

必须：

```text
Git
Node.js 24 LTS
```

可选：

```text
Codex CLI
Oh My Pi / OMP
```

Continuum 不依赖 Docker、常驻 Daemon、Redis、MySQL 或外部服务。

## 2. 安装方式

### 2.1 GitHub 全局安装

```bash
git clone --depth 1 https://github.com/yuanyi1415/Continuum.git
cd Continuum
bash install.sh
```

安装过程会通过 `prepare` 自动编译 TypeScript。

验证：

```bash
continuum --version
continuum --help
```

如果仓库是 private，Git 必须已经具备 GitHub 访问权限。

### 2.2 源码安装

```bash
git clone https://github.com/yuanyi1415/Continuum.git
cd Continuum
npm install
npm run build
npm link
```

## 3. 在项目中启用

Continuum 只在 Git Repository 内工作。

```bash
cd /path/to/your-project
git status
continuum init --name "Your Project"
```

初始化后：

```text
.continuum/          # Durable / Git-tracked
.continuum-local/    # Runtime / gitignored
```

不要把 `.continuum-local/` 提交到 Git。

## 4. 接入 Coding Agent

### Codex

```bash
continuum host install codex
continuum host doctor
```

安装内容是 repo-local 的 Codex Hook / MCP 配置，不修改 Continuum Core 语义。

### OMP

```bash
continuum host install omp
continuum host doctor
```

安装内容是项目内 OMP Extension。

## 5. 第一次检查

```bash
continuum status
continuum doctor
continuum host doctor
```

预期：

- Durable Project 可读；
- Runtime 可用或可重建；
- Current Snapshot 有效；
- 启用的 Host Adapter 不漂移。

## 6. 正式 Work

Continuum 不会把每一次聊天都当作正式开发任务。

正式 Ticket 建议先作为 Artifact 注册或通过 Matt scan 进入 Artifact Graph，然后以明确意图进入实现：

```text
implement P03
```

Work 建立时会冻结：

```text
worktree
Ticket
Change
work_start_revision
```

新的 Session 或另一个 Host 在同一 worktree 中可以恢复这份连续性。

## 7. 设计冲突

如果实现继续下去会违背当前 Spec / ADR，Continuum 会暂停当前正式 Work，让用户回到设计层处理。

设计材料真正更新后，再次发起：

```text
implement <Ticket>
```

Continuum 会比较阻断时与当前 Authority 版本，并要求用户确认是否基于新设计重新开始。

## 8. 项目维护

```bash
continuum doctor
continuum doctor --recover
continuum migrate
```

关键原则：

> 能确定恢复的 Runtime State 才自动恢复；Durable Authority 不明确时 fail-closed。

## 9. 项目归档

```bash
continuum archive
```

可选完整 Git History：

```bash
continuum archive --with-history
```

验证归档：

```bash
continuum archive verify <archive-path>
```
