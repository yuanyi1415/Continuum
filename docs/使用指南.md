# Continuum 使用指南

## 1. 启用项目

```bash
continuum init --name "My Project"
continuum status
```

如果使用 Codex / OMP，再安装对应 Host Adapter。

## 2. 开一个正式 Change

```bash
continuum change open "User Memory" --intent "实现用户长期 Memory"
```

Continuum 的 Change 是一个需要最终收敛到新 Snapshot 的正式变化范围。

## 3. 登记项目 Authority

可以通过 Matt scan：

```bash
continuum matt scan
```

也可以使用 CLI 显式登记：

```bash
continuum artifact register docs/spec.md --type spec --id SPEC-MEMORY
continuum artifact register docs/P03.md --type ticket --id P03
```

## 4. 开始正式 Work

在 Codex / OMP 中使用明确实现意图：

```text
implement P03
```

Continuum 会建立 Work Binding，并冻结当前 `work_start_revision`。

普通聊天、解释代码、临时研究不会自动升级成正式 Work。

## 5. 开发过程中

继续正常使用原 Coding Agent。Continuum 在背后维护：

```text
当前 Ticket
当前 Change
Work Baseline
相关 Spec / ADR / CONTEXT
当前 Git delta
Pending Reconcile
```

## 6. 遇到设计冲突

用户看到的是：

```text
发现设计冲突
→ 回到设计处理
```

此时当前 Work 被释放，但 Change 仍 active。你可以正常修改 Spec / ADR。

修改完成后再次：

```text
implement P03
```

如果相关 Authority 已更新，Continuum 会询问是否基于最新设计重新开始 Work。

## 7. Reconcile

```bash
continuum reconcile
```

Work Reconcile 从被冻结的 Work Baseline 计算 Git delta，不把绑定前的改动错误算入当前 Work。

Change 满足收敛条件后：

```bash
continuum reconcile --change <change-id>
```

成功后生成新的 immutable Snapshot，并推进 Current。

## 8. 日常健康检查

```bash
continuum doctor
continuum host doctor
```

Runtime 丢失或损坏时：

```bash
continuum doctor --recover
```

## 9. 项目完成归档

```bash
continuum archive
```

如果希望同时保存完整 Git History：

```bash
continuum archive --with-history
```

归档离开原 Repository 后仍可：

```bash
continuum archive verify <archive-path>
```

## 10. 推荐心智模型

```text
Git            = 代码版本事实
Spec / ADR     = 设计 Authority
Coding Agent   = 实际工作者
Continuum      = 项目生命周期控制面
```

Continuum 的目标不是要求用户学习更多命令，而是让长期 AI Coding 项目的关键状态不再只存在于某个 Agent Session 的上下文里。
