# P10｜Project Archive 实现说明

## 目标

把完成态 Live Federated Project 物化成可独立保存、离线理解和校验的 self-contained Project Archive。

## 冻结语义

```text
Live Project
→ Current Final Snapshot
→ Final Repository Revision
→ Durable Continuum State
→ Required Artifact Authorities
→ Final Source Snapshot
→ Manifest + checksums
→ Archive
```

Archive 不参与日常 Runtime，也不改变 Project / Change / Work / Snapshot 状态。

## CLI

```bash
continuum archive
continuum archive --allow-incomplete
continuum archive --with-history
continuum archive verify <archive-path>
```

所有命令支持 `--json`。

## 默认输出

```text
.continuum/archives/archive_<id>/
├── manifest.yaml
├── checksums.sha256
├── continuum/
│   ├── project.yaml
│   ├── current.yaml
│   ├── snapshots/
│   ├── changes/
│   ├── artifacts/
│   ├── relations/
│   └── reconciles/
├── artifacts/
│   ├── context/
│   ├── adr/
│   ├── spec/
│   ├── tickets/
│   └── evidence/
└── source/
    ├── snapshot/
    └── history.bundle   # only --with-history
```

## 关键实现约束

1. Final Source Snapshot 使用 Current Snapshot 中与 Project Repository Identity 匹配的 baseline revision，不使用当前 HEAD 猜测最终版本。
2. Materialized ADR / CONTEXT / Spec / Ticket / Evidence 同样读取 Final Snapshot revision 中的 Git blob。
3. Archive 前要求所有 Change 已 closed / superseded，Final Snapshot 无 blocker。
4. Required artifact 无法物化时默认 `CONTINUUM_ARCHIVE_INCOMPLETE`；只有 `--allow-incomplete` 可显式生成 incomplete Archive。
5. `document / other` 在 MVP 记录为 unsupported，不作为 self-contained 完整性硬门。
6. `--with-history` 使用 Git bundle 保存完整历史；默认只保存 Final Source Snapshot。
7. Archive 先在 `.continuum-local/archive-staging/` 构建并自校验，通过后再原子移动到 Durable Archive 目录。
8. `checksums.sha256` 覆盖 Archive 内除 checksum 文件本身外的所有普通文件/符号链接；`archive verify` 可在原 Repo 消失后独立运行。

## Architecture Gap

P10 实施未发现新的 Architecture Gap。既有冻结结论“Live Project = Federated Authority；Archive = self-contained materialization”可以直接落地。
