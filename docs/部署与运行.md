# Continuum 部署与运行方式

## 1. Continuum 不需要服务端部署

Continuum MVP v1.0 是 **local-first CLI**，不是需要长期运行的 Web Service。

正常运行结构：

```text
Developer Machine
├─ Git
├─ Node.js 24 LTS
├─ Continuum CLI
├─ Codex / OMP（可选）
└─ Your Git Projects
   ├─ .continuum/          # Git-tracked durable project state
   ├─ .continuum-local/    # local runtime SQLite
   ├─ .codex/              # optional Codex adapter
   └─ .omp/extensions/     # optional OMP adapter
```

因此不需要：

- Docker Compose；
- 常驻 Continuum daemon；
- MySQL / PostgreSQL；
- Redis；
- 单独部署服务器。

## 2. 推荐部署形态：本机全局 CLI

每台开发机安装一次：

```bash
npm install -g "github:yuanyi1415/Continuum"
```

验证：

```bash
continuum --version
```

然后每个 Git 项目按需启用：

```bash
cd your-project
continuum init --name "Your Project"
```

Continuum 只管理显式初始化过的项目。

## 3. Codex 部署

```bash
cd your-project
continuum host install codex
continuum host doctor
```

Continuum 会安装项目级 Codex Hook / MCP 配置。后续仍然直接启动：

```bash
codex
```

Continuum 不包裹 Codex 进程，也不接管 Codex Runtime。

## 4. OMP 部署

```bash
cd your-project
continuum host install omp
continuum host doctor
```

然后仍然直接：

```bash
omp
```

Continuum 通过项目级 Extension 接入 OMP。

## 5. 团队使用

`.continuum/` 应进入 Git，它代表可迁移的项目事实。

`.continuum-local/` 必须保持本地，不提交 Git。它包含可以重新推导的 Runtime State。

当另一名成员 clone 项目后：

```bash
npm install -g "github:yuanyi1415/Continuum"
cd cloned-project
continuum migrate
continuum doctor --recover
continuum host install codex   # 按实际 Host
continuum host install omp     # 按实际 Host
continuum status
```

## 6. 升级

GitHub 安装方式升级到最新 main：

```bash
npm install -g "github:yuanyi1415/Continuum"
```

升级 CLI 后，在已有项目运行：

```bash
continuum migrate
continuum doctor
```

Continuum 对不认识的更高版本 Durable Schema 会 fail-closed，不会尝试猜测降级。

## 7. Docker 的位置

Continuum 本身不依赖 Docker。

未来如果 Coding Agent 的命令执行需要隔离，可以在外层使用 Docker / Podman / Sandbox；这是 **Execution Isolation**，不是 Continuum 的部署依赖。
