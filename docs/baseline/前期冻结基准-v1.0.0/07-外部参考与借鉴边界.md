# 07｜外部参考与借鉴边界

本文件只保留对 Continuum 最终设计产生实际影响的外部参考。

---

## 1. Matt Pocock Skills

### 采用

作为 Development / Discovery 主流程：

- CONTEXT；
- grill-with-docs；
- research；
- prototype；
- wayfinder；
- to-spec；
- to-tickets；
- implement；
- code-review。

### 不采用

不把 Continuum 再设计成一套平行 Spec / Ticket / TDD 系统。

---

## 2. OpenSpec

### 借鉴

- Current Specs vs Active Changes；
- Change Lifecycle；
- Archive；
- Delta / convergence 思路。

### 不采用

不引入一套与 Matt 重叠的完整 Spec Workflow。

---

## 3. GitHub Spec Kit

### 借鉴

- implementation 后 Converge；
- living / flow-forward / flow-back 的持久化思路；
- Reconcile 作为正式阶段。

---

## 4. CodeGraph

### 借鉴

- 一个 Core，多 Surface；
- cwd / workspace 自动发现；
- CLI / MCP / IDE 共用底层；
- 工具 Surface 尽量小；
- Agent Rules 决定“什么时候用”。

### 对 Continuum 的影响

强化：

```text
One Core
+ Host Adapters
+ Minimal Agent Surface
```

---

## 5. i-have-adhd

### 借鉴

- 安装与激活分离；
- Explicit / Implicit / Always-on 思路；
- Agent-assisted install；
- 当前 Session 可关闭。

### 对 Continuum 的影响

最终演化为：

```text
Project Opt-in
+
Existing-intent Activation
+
Session Suppression
```

---

## 6. Ponytail

### 借鉴

- Lifecycle Hooks；
- Mode / 状态可见；
- Escape Hatch；
- Graceful Degradation；
- 不同 Agent 使用不同原生接入方式。

### 对 Continuum 的影响

强化：

```text
Native Integration
→ UX 上限

CLI / Rules / Git
→ 兼容与 Correctness 下限
```

---

## 7. Beads

### 当前状态

Deferred。

只有当：

- Ticket 依赖图；
- discovered-from；
- ready queue；

真正成为瓶颈时再考虑。

不进入 MVP 核心。

---

## 8. Serena / Repo Map 类能力

### 当前状态

Deferred / Optional。

Context Routing 已证明 Typed Relations + Authority 可以覆盖 MVP。

未来如代码上下文检索成为瓶颈，再引入动态代码索引。

---

## 9. BMAD / CCPM / Agent OS / Ruler

只借鉴局部思想：

- role separation；
- standards routing；
- multi-agent rules consistency；
- parallel workflow。

不作为 Continuum 核心依赖。

---

## 10. 外部参考总原则

> **借结构，不复制产品；借已验证交互，不继承不需要的复杂度。**

Continuum 应始终围绕自己的核心问题：

> **长期 AI Coding 项目的连续性与一致性。**
