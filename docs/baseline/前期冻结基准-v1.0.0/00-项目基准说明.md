## 1. 这份基准的作用

本包是 Continuum 在正式建设前的唯一前期事实基准，用于回答：

- Continuum 为什么存在；
- 它解决什么、不解决什么；
- 核心领域对象与权威边界是什么；
- Agent 什么时候进入 Continuum 管理；
- Codex / Oh My Pi 如何接入；
- 生命周期何时自动触发、何时必须问人；
- 哪些结论已经经过 Spike 验证；
- 下一阶段还需要正式设计什么。

后续如无新的反证，不再回退到前期已被淘汰的方案。

---

## 2. 一句话定义

> **Continuum 是一个面向长期 AI Coding 项目的轻量 Project Control Plane，用来让项目在持续变化、跨 Session、跨 Agent 的过程中，始终保持当前状态、工作边界、Artifact 权威与项目认知的一致性。**

它不负责替代 Coding Agent，也不重新发明 Spec、Ticket、TDD、实现和 Review。

---

## 3. 核心使命

> **Keep the project coherent as it changes.**

中文：

> **让项目在持续变化中始终保持清晰与一致。**

---

## 4. 本阶段最终冻结的核心判断

1. **Matt Pocock Skills 继续作为开发主流程。**
2. **Continuum 只补长期 Project State / Lifecycle / Context Routing / Reconcile。**
3. **Continuum 是 Project-scoped、opt-in，而不是所有 Agent 任务的全局 Runtime。**
4. **关键状态迁移不得仅依赖 LLM 主动性。**
5. **Lifecycle 正确性由状态事实推导，Host Hook 只负责低延迟唤醒。**
6. **Worktree 是跨 Agent 的工作连续性边界，Session 只是临时交互边界。**
7. **Ticket Reconcile 从 Work Baseline 开始，不从 Project Snapshot Baseline 开始。**
8. **Ticket Reconcile 默认是临时过程；Change Reconcile 才是长期持久化边界。**
9. **不同 Agent 共用统一 Interaction 语义，但按宿主原生 UI 渲染。**
10. **正常成功默认静默，只有真正需要人的 DECISION / BLOCK 才打断用户。**
