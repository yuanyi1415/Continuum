# 06｜下一阶段入口

Continuum 已完成：

```text
Know the World
→ Unknown Register
→ Risk Ranking
→ Proof Plan
→ Spike / Evidence
→ Architecture Gate
```

现在可以进入：

```text
Formal Architecture
→ ADR
→ Spec
→ Tickets
→ Build
```

---

## 2. 下一阶段不要再重复讨论的内容

除非出现反证，不再重新争论：

- Continuum 是否应该替代 Matt；
- 是否所有 Agent Task 都要跑 Continuum；
- 是否依赖 LLM 主动更新；
- 是否应该做全局后台 Runtime；
- Ticket Reconcile 是否要每 Ticket 持久化 Git Artifact；
- Worktree / Session 谁负责跨 Agent Continuity；
- Codex 是否需要常驻 Status；
- OMP 是否同时堆多种 Continuum 状态 UI；
- MVP 是否需要 RAG / Vector DB / Knowledge Graph；
- 是否需要 Beads / BMAD / CCPM 作为核心依赖。

这些已由前期分析或 Spike 给出足够答案。

---

## 3. 下一阶段真正需要正式设计的内容

### A. Core Module Boundary

冻结代码模块：

```text
project
snapshot
change
artifact-ref
relation
work-binding
lifecycle
reconcile
interaction
archive
```

明确依赖方向和接口。

---

### B. Durable Storage Format

当前只冻结：

```text
.continuum/ = durable
.continuum-local/ = ephemeral
```

尚未冻结：

- YAML / JSON；
- SQLite；
- event log；
- directory layout；
- schema migration。

这属于正式架构设计问题。

---

### C. Lifecycle State Machine

正式定义：

- Project；
- Change；
- Work；
- Reconcile；
- Archive；

各自允许的状态和迁移。

不要把 Spike Prototype 的临时状态名直接带进正式实现。

---

### D. Interaction Schema

正式定义统一：

```text
STATUS
NOTICE
DECISION
BLOCK
```

的 schema：

- id；
- type；
- title；
- context；
- options；
- blocking；
- reason；
- result；
- capability fallback。

---

### E. Host Adapter Contract

正式定义：

```text
detect_project()
resume_work()
observe_intent()
checkpoint()
render_interaction()
suppress_session()
```

Codex / OMP 只是第一批 Adapter。

---

### F. Reconcile Contract

正式冻结：

- Inputs；
- Work Baseline；
- Evidence；
- Knowledge Impact；
- AUTO / PROPOSE / STOP；
- Change Reconcile output；
- Snapshot advancement。

---

### G. Matt Adapter

正式定义 Continuum 如何：

- 识别 Spec；
- 识别 Ticket；
- 识别 `/implement` 等明确 Intent；
- 建立 Relation；
- 不侵入 Matt Skill 本身。

---

### H. Archive

MVP 需要提前定义最小 Archive 边界：

```text
Live Project
= Federated Authority

Project Archive
= Materialized self-contained snapshot
```

但个人知识提取仍延后。

---

## 4. 推荐先形成的 ADR

建议下一阶段先写：

1. **ADR｜Continuum 采用 Project-scoped Opt-in**
2. **ADR｜State-derived Lifecycle + Event-assisted Trigger**
3. **ADR｜Durable Project State 与 Ephemeral Runtime State 分离**
4. **ADR｜Worktree Continuity + Session Suppression**
5. **ADR｜Federated Artifact Authority**
6. **ADR｜Ticket Ephemeral Reconcile + Change Durable Reconcile**
7. **ADR｜Host-native Interaction Model**
8. **ADR｜Matt Black-box Integration**

这些 ADR 写完后再进入第一版 Spec。

---

## 5. 第一版 Spec 应控制范围

MVP 只需要证明一个完整闭环：

```text
continuum init
↓
detect project
↓
open / detect Change
↓
bind Ticket
↓
route minimal context
↓
Agent works
↓
lifecycle checkpoint
↓
ticket reconcile
↓
change reconcile
↓
new snapshot
↓
resume from another Agent
```

不做：

- Web Dashboard；
- Knowledge Graph；
- Personal Knowledge Extraction；
- 多 Agent Scheduler；
- 云端服务；
- 复杂权限系统；
- 全量 IDE 插件生态；
- 独立 Issue Tracker。

---

## 6. 下一阶段完成标准

只有当正式架构能够回答下列问题时，才进入编码：

1. Current Project State 的唯一事实在哪里？
2. Change / Work / Session 的边界是什么？
3. 各 Artifact 的 Authority 谁拥有？
4. durable / ephemeral 数据如何落盘？
5. Hook 丢失如何恢复？
6. Agent 切换如何 resume？
7. Ticket / Change Reconcile 如何区分？
8. Host Interaction 如何降级？
9. 并行 worktree 如何避免状态冲突？
10. Archive 如何保证项目最终自包含？

---

## 7. 项目启动红线

> **当我们还不知道自己不知道什么时，不进入正式建设。**

这一轮前期工作已经达到了进入下一阶段的条件。

后续正式开发仍应坚持：

```text
Architecture Gap
→ 先更新 System Model / ADR
→ 再拆 Ticket
```

而不是：

```text
发现问题
→ 立刻再开几个实现 Ticket
```
