# 02｜模块分层与工程结构

## 1. 正式分层

```text
Domain
↑
Application
↑
Ports
↑
Adapters / Infrastructure
↑
CLI / Host Integration
```

更准确的依赖规则：

```text
Domain
  不依赖任何外层

Application
  依赖 Domain + Port Interface

Ports
  只定义抽象契约

Adapters
  实现 Ports / Host Integration

CLI
  负责 composition root
```

## 3. 模块职责

### Domain

包含：

- Entity / Value Object；
- Invariant；
- Domain Transition；
- 纯判断逻辑。

禁止：

- 读文件；
- 跑 Git；
- 调 MCP；
- 读取环境变量；
- 依赖 Host SDK。

### Application

负责 Use Case 与编排：

```text
InitProject
GetStatus
OpenChange
CloseChange
SupersedeChange
RegisterArtifact
RegisterRelation
BindWork
SuppressSession
HandleLifecycleSignal
ReconcileWork
ReconcileChange
RouteContext
ResolveInteraction
ArchiveProject
Doctor
```

### Ports

提供外部依赖抽象。

### Adapters

包含所有不稳定边界：

- Git；
- Filesystem；
- SQLite；
- Codex；
- OMP；
- Matt；
- Test / CI；
- MCP。

---

## 4. 禁止依赖规则

必须通过 lint / architecture test 约束：

```text
domain → adapters      禁止
domain → application   禁止
application → adapters 禁止
ports → adapters       禁止
```

允许：

```text
application → domain
application → ports
adapters → ports
adapters → domain types（只读 DTO 时允许）
cli → application + adapters
```

---

## 5. 扩展点

新增 Claude / OpenCode 时：

```text
新增 adapters/hosts/<host>
```

不应修改：

- Change；
- Work；
- Reconcile；
- Snapshot；
- Context Router。

新增 Artifact Provider 时：

```text
新增 ArtifactAuthorityPort implementation
```

新增 Runtime DB 时：

```text
新增 RuntimeStorePort implementation
```
