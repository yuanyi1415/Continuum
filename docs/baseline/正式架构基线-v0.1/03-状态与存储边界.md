# 03｜状态与存储边界

## 1. 两类状态必须物理分离

### Durable Project State

```text
.continuum/
```

特点：

- Git tracked；
- 可 clone；
- 可 review；
- 项目级；
- 跨 Agent；
- 跨机器。

### Ephemeral Runtime State

```text
.continuum-local/
```

特点：

- gitignored；
- 高频写；
- 当前机器 / 当前 worktree；
- Session / binding / pending candidate；
- 可从 Authority 恢复。

---

## 2. Durable State 候选结构

```text
.continuum/
├── project.yaml
├── current.yaml
├── snapshots/
├── changes/
├── artifacts/
├── relations/
├── reconciles/
└── archive/
```

注意：

> 该目录结构是架构候选，不在本轮冻结具体序列化格式。

---

## 3. Ephemeral State 候选结构

逻辑上至少包含：

```text
Runtime Binding
Session Suppression
Pending Ticket Reconcile
Host Event Cursor
Transient Signal
```

实现可采用：

- SQLite；
- files；
- embedded KV。

正式选择交给 Storage ADR。

---

## 4. Current Pointer

`current` 只能由高层收敛点推进：

```text
Change Reconcile
→ New Immutable Snapshot
→ Current Pointer update
```

禁止：

```text
每个 Tool Call
每个 Commit
每个 Ticket
→ 修改全局 Current Snapshot
```

---

## 5. 并发规则

### Ticket / Work 级

并行 Agent：

- 只操作各自 worktree local runtime；
- 不推进 global snapshot；
- 不争抢同一 durable state 文件。

### Change 级

进入 Integration / Change Reconcile 后：

- 汇总 Ticket facts；
- 形成 Change Result；
- 一次推进 Snapshot。

---

## 6. 可恢复性

Ephemeral Runtime State 丢失不能破坏 Correctness。

系统必须可通过：

```text
Current Snapshot
+
Git
+
Tracker
+
Authority Artifacts
+
Tests / Evidence
```

恢复：

- unreconciled work；
- pending change；
- current baseline difference。

---

## 7. Schema Version

Durable state 必须带 schema version。

目标：

```text
continuum init
→ schema_version = N
```

以后升级通过显式 migration。

禁止让不同版本 Core 默默解释不兼容状态。

---

## 8. 当前待 ADR 决策

尚未正式冻结：

- durable format：YAML / JSON / 混合；
- runtime store：SQLite / files；
- relation physical layout；
- generated index 是否持久化；
- schema migration strategy。

这些属于正式 Architecture ADR，而不是 Spike 阶段事实。
