# 02｜核心模块与依赖边界

## 1. 模块总览

正式候选模块：

```text
project
snapshot
change
work
artifact
relation
lifecycle
reconcile
context
interaction
archive
```

其中：

- `project / snapshot / change / work / artifact / relation / reconcile / interaction`
  属于 Domain Core；
- `lifecycle / context / archive`
  主要属于 Application Service；
- Host-specific 行为全部位于 Adapter。

---

## 2. project

### 拥有

- Project Identity；
- Project Metadata；
- Current Snapshot Pointer；
- Project lifecycle status。

### 不拥有

- Ticket；
- Spec 内容；
- Agent Session；
- Git branch 状态。

---

## 3. snapshot

Snapshot 表示：

> **某个时点 Continuum 对“项目现在是什么”的不可变描述。**

建议最小包含：

```yaml
snapshot_id:
project_id:
created_at:
baselines:
  repositories: []
stage:
active_changes: []
blockers: []
next_gate:
last_reconcile:
```

原则：

- Immutable；
- Current 只是指向 Snapshot；
- 不塞入可从其它 Authority 推导的所有细节。

---

## 4. change

Change 表示：

> **一次需要被长期追踪的正式项目变化。**

拥有：

- Change identity；
- title / intent；
- lifecycle status；
- Spec references；
- Ticket references；
- change-level reconcile references。

不拥有：

- Spec 正文；
- Ticket 正文。

---

## 5. work

Work 表示：

> **当前工作树中正在执行的一项正式工作。**

MVP 中主要映射到 Ticket / Work Item。

拥有：

- work identity；
- target reference；
- worktree identity；
- `work_start_revision`；
- binding metadata。

### 关键边界

```text
Project Snapshot Baseline
≠
Work Baseline
```

Work Baseline 在首次正式绑定时冻结。

---

## 6. artifact

ArtifactRef 只保存：

```text
type
authority
locator
version / revision
metadata
```

不默认保存正文复制。

---

## 7. relation

Relation 表达跨 Artifact 的显式语义。

候选关系：

```text
belongs_to
blocked_by
governed_by
domain_context
evidence
historical
optional
```

原则：

- relation 本身属于 Continuum Authority；
- Artifact 内容仍属于原系统 Authority；
- Context Router 主要依赖 Relation 做显式路由。

---

## 8. lifecycle

Lifecycle Engine 是 Application Service，不是 Domain Entity。

输入：

```text
LifecycleSignal
+
Authoritative State
+
Runtime Binding
```

输出：

```text
LifecycleAction
```

例如：

```text
NOOP
CHECK_WORK
RECONCILE_WORK
RECONCILE_CHANGE
REQUEST_DECISION
BLOCK
```

---

## 9. reconcile

Reconcile 是：

> **对“预期状态”与“当前真实状态”进行收敛判断。**

分两层：

```text
Ticket / Work Reconcile
Change Reconcile
```

Ticket Reconcile 默认 ephemeral。

Change Reconcile 形成 durable result，并允许推进 Snapshot。

---

## 10. context

Context Router 不是一个新的知识库。

职责：

```text
Current Work
+
Typed Relations
+
Authority Index
→ Minimal Required Context
```

默认不加载 Historical / Optional。

---

## 11. interaction

统一只有四类：

```text
STATUS
NOTICE
DECISION
BLOCK
```

Domain / Application 只产生 InteractionRequest。

具体：

- Codex MCP Elicitation；
- OMP Select；
- OMP Overlay；
- Hook Block；

由 Host Renderer 决定。

---

## 12. archive

Archive 负责把 live federated project：

```text
Git
Tracker
CONTEXT
ADR
Spec
Ticket
Continuum State
```

在项目结束时物化成可独立保存的 self-contained Project Archive。

Archive 不进入第一阶段日常 Runtime。
